# 01｜证据分级与版本分流

用本区判断一条说法有多可靠、何时选 2.0 或 2.5，以及哪些产品事实必须重新查证。

## 证据等级

### A｜官方

当前平台、当前入口、当前版本的官方指南、帮助文档或 API 文档明确写出。

用途：

- 确认模型、入口、时长、素材类型、参数和语法。
- 建立能力边界。
- 处理版权、真人、地区或接口限制。

注意：不同入口可能不同；旧官方页面也可能过期。

### B｜成片验证

成片、原提示词、素材、设置和生成日期能够配对复盘。

用途：

- 在原任务中优先保护。
- 迁移时从最小变量开始。
- 记录成功机制和已知缺陷。

单条成片只证明“这一组合可工作”，不自动证明普遍机制。

### C｜稳定经验

多次项目生成中重复成立，或与官方能力、现场物理和导演逻辑一致。

用途：

- 作为 JIN 默认生产规范。
- 继续记录适用范围和反例。

### D｜假设／圈内术语

来自单次案例推断、第三方截图、社群叫法、架构类比或尚未完成 A/B 的策略。

用途：

- 只用于设计实验。
- 不得写成模型官方原理。
- 失败时可以回滚，不保护其措辞。

## 事实陈述格式

输出分析时尽量显式区分：

- 官方明确支持：仅用于 A 级事实。
- JIN 当前默认：用于 C 级生产策略。
- 当前成片显示：用于 B 级具体结果。
- 工作假设／待验证：用于 D 级。

不要用“模型就是这样”“官方机制是”包装项目经验。

## 官方能力与生产默认值

### Seedance 2.0

Seedance 2.0 的官方能力不能被简化成只能处理 4–10 秒、单动作或简单镜头。已对照资料显示它也可能支持复杂物理、多模态参考、15 秒多镜头与较长脚本；具体能力由平台和入口决定。

JIN 默认生产路径：

- 常从 4–10 秒最小可验证镜头开始。
- 一个中心动作或情绪节拍。
- 一个主要摄影机任务。
- 明确起始姿态、运动路径、物理结果和结束状态。
- 保留少量模型补全空间，但不把关键连续性留白。

### Seedance 2.5

JIN 默认生产路径：

- 15–30 秒连续叙事、状态转换、延长或编辑。
- 按阶段或关键状态推进，每段都继承上一段的真实结果。
- 更完整地覆盖时间，不让未安排时段只剩展示性停留。
- 可使用多模态参考，但仍以少而清楚、职责单一为先。

JIN 当前关于“2.5 更忠实执行、2.0 更会补空白”的结论属于项目工作假设。尤其 30 秒动作密度结论目前源于少量成片复盘，继续作为 B/C 级经验测试，不能写成官方架构差异。

## 版本选择矩阵

| 判断维度 | 更接近 2.0 默认路径 | 更接近 2.5 默认路径 |
|---|---|---|
| 时长 | 4–10 秒或一个短节拍 | 15–30 秒或连续延长 |
| 中心变化 | 一个动作、表情或互动 | 多个相继状态变化 |
| 连续性 | 单镜头内清楚即可 | 多阶段、长路径或跨空间继承 |
| 素材职责 | 少量角色／动作参考 | 多模态角色、场景、视频、声音分工 |
| 文本密度 | 起点、路径、结果为核心 | 全时间覆盖、阶段结束状态更明确 |
| 生成方式 | 独立短镜头、小测试 | 长叙事、延长、编辑、复杂参考 |

这只是默认选择工具。若用户指定版本或入口，以用户要求和当前官方能力为准。

## 时长与动作密度

### 4–10 秒

- 一个中心事件。
- 约 2–4 个可见动作节点。
- 一个主要运镜。
- 结尾留出短暂停留，让结果可读。

### 15 秒

- 一个主事件弧，可含 2–3 个阶段。
- 每阶段一个主要变化。
- 复杂追拍通常只保留一条主追拍、两次以内主要遮挡、一次可选焦点切换和一个明确终点。

### 30 秒

- 约三条普通 10 秒提示词的可见内容量。
- 目标约 9–12 个可执行节点，每节点约 2–4 秒。
- 每约 10 秒内部段落具备起点、行动、摄影机任务和结果。
- 三阶段不是强制；按事件密度调整。
- 若五个独立事件互相竞争，先删事件或拆片。

不按每秒硬塞一个命令。全时段覆盖指的是持续的可见因果，不是极端动作堆叠。

## 生成方式分流

### 文生视频

把身份、场景、起点、路径、结果、镜头和声音都写清。不要假设模型知道角色外观或空间。

### 图生视频

先说明图片负责身份、构图还是场景；写明哪些静态状态要保持、哪些要改变。不要重复描述图片中已经稳定且无歧义的细节。

### 参考视频

拆分要继承的动作、节奏、表演或摄影机轨迹；明确不继承人物、服装、场景、色调、字幕和水印等内容。

### 首尾帧

把首帧当起始状态，把尾帧当必须到达的结果。补写中间的物理路径，不能只说“从图一变到图二”。

### 延长／续写

以实际接受成片的尾帧状态开始，记录人物、道具、摄影机、光、声和未完成惯性，再写一个新的中心事件。

### 编辑

明确保留项、替换项和局部变化范围。不要让一次编辑同时承担身份、动作、镜头、光影和场景的全面重写。

## 需要即时核验的事项

遇到以下问题，必须查对应平台当日官方资料：

- 当前最长时长、分辨率、画幅和素材数量；
- 定价、额度、地区、排队或商业授权；
- API 字段、模型 ID、上传格式和文件大小；
- 真人、名人、版权角色、声音克隆和内容政策；
- 某个标签或特殊语法是否被当前入口支持；
- 2.0／2.5 的具体可用模式。

查证时优先使用平台官方文档，不用旧项目经验代替。

## 不得冒充官方的术语

以下内容只能按内部工具或未验证说法处理：

- C1／C2／C3：JIN 的连续性检查点，不是平台标签。
- Boss 正面、环境垫图：社群工作话语，正式提示词要换成真实素材标签与职责句。
- 固定全局运动轴：可作为复杂连续运动的设计策略，不是所有任务的官方要求。
- 隐藏转场、长镜头优先：是导演策略，不是 2.5 的已证实稳定性机制。
- MMDiT、RayFlow、双分支等架构名：没有当前官方技术原文时不参与提示词决策。
